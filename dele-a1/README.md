# DELE A1 · 阅读 + 写作练习册

把 Instituto Cervantes 官方公开的 **4 套 A1 试卷**做成可作答、可判分的单文件 HTML。
沿用 `../quiz_kit/quizkit.py` 判分引擎（与 TOEIC / AWS 题库同一套交互）。

## 打开方式

直接双击 `out/index.html`（纯静态，无需服务器；图片是相对路径 `out/img/`）。
进度存在浏览器 localStorage（key = `quiz:dele-a1-<slug>`），换设备不共享。

## 界面：电脑 / 手机两套 UI（同一份文件）

不用做两份 HTML —— 靠 CSS 媒体查询按屏幕宽度自动切换，浏览器自己判断：

| | **电脑（≥1080px）** | **手机（≤640px）** |
|---|---|---|
| 版式 | 左侧 300px 常驻侧栏 + 右侧题目（双栏） | 单列全宽 |
| 操作区 | 侧栏竖排按钮 + 统计 + 进度条 | 顶部 sticky 一行，可横向滑动 |
| 触摸目标 | 常规 | 按钮 **≥44px**（iOS 建议值） |
| 宽表格 | 完整显示 | 横向滑动 + 「← 左右滑动查看 →」提示 |
| 答题卡 | 右下角浮动面板 | 底部通栏浮层 |
| 首页卡片 | 4 列 | 单列 |

断点：`≤640` 手机 · `641–1079` 平板/小笔记本（单栏居中）· `≥1080` 桌面双栏。

实现要点在 `build.py` 的 `RESP_CSS`：**响应式样式必须拼在引擎 CSS 之后**
（引擎 `quizkit.py` 里 `.qbar` / `.sheet` 等同名规则、以及 `max-width:560px` 下的
`!important` 收缩规则会覆盖先加载的 `BASE_CSS`，只有放到最后才压得住）。

## 验证覆盖（`test_dele.py`，当前全绿）

- 每页 `.q` 数量 = 25；无 JS 报错
- 全选对 → 正确率 **100%**、已答 25；交卷成绩单一致
- 全选错 → 正确率 **0%**
- 「展开全部解析」25/25 开 → 再点 25/25 关
- 「只看错题」：全对时显示 0 题、全错时显示 25 题
- 填空容错：`lunes` / `el viernes` / `miercoles` / `futbol` 等无重音写法判对；`18 → martes` 判错
- 手机视口 375×812：4 套均无横向溢出，答题卡浮层不超出视口
- 首页 4 张卡片

### 双端布局验收（2026-10-08 补充）

- **7 种视口 × 5 个页面 = 0 横向溢出**：360 / 375 / 414 / 768 / 1024 / 1366 / 1920
- 断点切换正确：≤1024 单栏（`display:block`）· ≥1366 双栏（`display:grid`）
- 桌面侧栏 `position:sticky`、宽 300px、正文宽 902～982px，滚动时侧栏不动
- 桌面答题卡定位在右下角（x = 视口宽 − 24 − 352）
- 手机按钮实测高 **44px**；顶部操作区单行可滑动（内容 398 > 可视 347）
- 跳题锚点：桌面 `.q` top = 18px（无固定顶栏，不用偏移）；手机 top = 工具栏高 + 16px
- 宽表滑动提示：桌面 `display:none`、窄屏 `display:block`，仅当内容溢出时才有意义

## 解析过程中的已知坑

1. **2020-07 真题的文本层是自定义字体编码**，`get_text()` 出来是乱码 → 逐页渲染 PNG 后视觉重建。
2. **多列/分栏排版 OCR 会串行** —— 匹配题的 A–J 卡片必须靠读图确认字母位置，不能信 OCR 顺序。
3. **2009 原卷印刷笔误**：行程表第 2、3 栏都印成 `MIÉRCOLES`。官方答案把"去购物"那天记为 `MARTES`，
   所以第 20 题 `MARTES` 与 `MIÉRCOLES` 两种写法都算对，页面里也加了提示框。
4. **图片选项**（每题第 5 题）用 PyMuPDF `get_image_info()` 取 bbox 后裁图，不是截图；
   2009 那题的 4 张裁图顺序与 PDF 视觉顺序不一致，已重命名修正。
