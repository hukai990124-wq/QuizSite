  1. 1.实现选择
    需求：让 .card 在其父容器 .wrap 内既水平居中、又垂直居中。下列实现正确的是：
    • A
      .wrap {
  display: flex;
  justify-content: center;
  align-items: center;
}
    • B
      .card {
  margin: auto;
}
    • C
      .wrap {
  text-align: center;
  vertical-align: middle;
}
    • D
      .card {
  justify-content: center;
  align-items: center;
}
    看解析
    正确答案：A A 是唯一能同时做到两轴的写法：justify-content 管主轴（默认横向），align-items 管交叉轴（默认纵向），两个都得给。 其余三个的真实表现： · B：margin:auto 只在 flex / grid 子项上才会垂直居中。父容器是普通块级时，它只吃掉左右剩余空间，垂直方向完全不动。 · C：text-align:center 只影响行内内容；vertical-align 只对行内元素和表格单元格生效，对块级子元素无效——这是最常见的误用。 · D：justify-content / align-items 是容器属性，写在子项上不产生任何效果。 延伸阅读：MDN · CSS Flexible Box Layout / vertical-align
  2. 2.实现选择
    需求：三个 .col 在容器内等宽平分，且不受各自内容长度影响。下列实现正确的是：
    • A
      .col {
  flex: 1;
}
    • B
      .col {
  flex-grow: 1;
}
    • C
      .col {
  width: 33.33%;
}
    • D
      .row {
  justify-content: space-between;
}
    看解析
    正确答案：A flex: 1 是 flex-grow:1; flex-shrink:1; flex-basis:0% 的简写——关键在 flex-basis:0%：先把所有子项的基础尺寸归零，再按 grow 比例分配剩余空间，所以内容长短不影响结果，三列严格等宽。 B 是最值得警惕的错法：单写 flex-grow:1 时 flex-basis 仍是 auto，浏览器会先按内容宽度分配，再分剩余空间。三列文字长度不一致时宽度就不等了——这段代码看起来「能跑」，但布局会随文案长度漂移，属于典型的隐性缺陷。 C：33.33% 没算上容器 padding 和列间距，且 flex 容器里宽度还会被 shrink 二次修正。 D：space-between 只管间距分配，不管宽度，三列仍由内容决定宽窄。 延伸阅读：MDN · flex 简写 / flex-basis
  3. 3.实现选择
    需求：单行文字超出容器宽度时显示省略号（…）。下列实现正确的是：
    • A
      .title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
    • B
      .title {
  text-overflow: ellipsis;
}
    • C
      .title {
  overflow: hidden;
  text-overflow: ellipsis;
}
    • D
      .title {
  white-space: nowrap;
  text-overflow: ellipsis;
}
    看解析
    正确答案：A 这三个属性是绑定套装，缺一不可，各自职责不同： · white-space:nowrap —— 强制不换行，制造「一行放不下」的前提 · overflow:hidden —— 真正把超出部分裁掉 · text-overflow:ellipsis —— 只在已经发生裁剪时才画省略号 B / D 没写 overflow:hidden：文字会直接溢出容器，省略号不会出现。 C 没写 nowrap：文字会正常折行显示，压根不产生溢出，省略号同样不会出现。 审查要点：看到 text-overflow 就往上翻两行确认另外两个在不在。 延伸阅读：MDN · text-overflow
  4. 4.实现选择
    需求：让图片在容器内等比缩放、不变形，且不超过容器宽度。下列实现正确的是：
    • A
      img {
  max-width: 100%;
  height: auto;
}
    • B
      img {
  width: 100%;
}
    • C
      img {
  object-fit: contain;
}
    • D
      img {
  max-width: 100%;
  height: 100%;
}
    看解析
    正确答案：A max-width:100% 只压上限、不放大，height:auto 让高度跟着按比例走——小图不会拉伸，大图不会溢出。A 是唯一同时满足「不变形 + 不溢出 + 不放大」的写法。 · B：width:100% 是无条件拉伸，一张 200px 的小图会被拉满容器变模糊。 · C：object-fit 管的是图片在自身盒子内怎么填充，它不会约束盒子尺寸——如果 img 本身已经超宽，照样溢出。 · D：height:100% 脱离了父容器高度时会被解析成 auto，就算生效也是强制拉伸，长宽比直接崩。 延伸阅读：MDN · max-width / object-fit
  5. 5.实现选择
    需求：让一个元素不可见、不响应鼠标点击，但仍保留它占据的布局空间。应该用：
    • A
      .item {
  visibility: hidden;
}
    • B
      .item {
  opacity: 0;
}
    • C
      .item {
  display: none;
}
    • D
      .item {
  position: absolute;
  left: -9999px;
}
    看解析
    正确答案：A 三种「看不见」的语义差别，是 review 时经常被搞混的一组： · visibility: hidden —— 保留占位、不响应点击、屏幕阅读器跳过 · opacity: 0 —— 保留占位、仍然响应点击、屏幕阅读器照样读 · display: none —— 不保留占位、不响应点击、完全移出渲染树 B 的坑最隐蔽：opacity:0 元素照样接收点击。如果它盖在按钮上方，用户会遇到「点不动」的诡异 bug。 C 会让布局塌陷，周围元素会跳位。 D 是老式的「移出屏幕」hack，会凭空撑出滚动区域，现在不该再出现。 延伸阅读：MDN · visibility / opacity
  6. 6.实现选择
    需求：给元素加一个 0.2 秒的过渡动画。从性能角度看，下列写法最合理的是：
    • A
      .box {
  transition: opacity .2s, transform .2s;
}
    • B
      .box {
  transition: all .2s;
}
    • C
      .box {
  transition: width .2s, height .2s,
              top .2s, left .2s;
}
    • D
      .box {
  transition: 0.2s;
}
    看解析
    正确答案：A transition: all 是 review 里见到就该拦下来的写法： · 它会监听每一个可动画属性，元素上任何样式变化都会触发过渡，包括你没预料到的（比如 JS 顺手改了个 padding） · 浏览器的插值计算量成倍上升，在低端机上直接掉帧 A 只声明 opacity 和 transform——这两个是合成属性，过渡过程可以完全交给 GPU，不触发重排（reflow）和重绘（repaint），是最廉价的一类动画。 C 过渡的四个属性全部会触发重排，每帧都要重新计算布局，是最贵的写法。 D 语法错误：transition 至少需要「属性 + 时长」，只给时长不生效。 延伸阅读：MDN · transition / 渲染性能：合成层
  7. 7.实现选择
    需求：字号要能跟随用户在浏览器里设置的根字号统一缩放（无障碍要求）。应该用哪个单位？
    • A
      .text {
  font-size: 1rem;
}
    • B
      .text {
  font-size: 1em;
}
    • C
      .text {
  font-size: 120%;
}
    • D
      .text {
  font-size: 2vw;
}
    看解析
    正确答案：A rem 始终相对根元素（html）字号，全站一个基准，改一处全站跟着变，并且尊重用户在浏览器里调整的默认字号——无障碍场景的标配。 B 是这条需求里最该避免的：em 相对父元素字号，会层层累积。嵌套列表里 font-size:0.9em 写三层，文字就缩到 0.9³ ≈ 0.73 倍，越往里越小。 C：百分比和 em 一样相对父级，同样存在嵌套累积问题。 D：vw 跟随视口宽度，跟用户设置的根字号无关；而且纯 vw 字号在超宽屏上会大到失控（通常要配 clamp() 夹住上下限）。 延伸阅读：MDN · CSS 值与单位 / rem vs em
  8. 8.实现选择
    下列 CSS 属性中，不会被子元素继承的是：
    • Awidth
    • Bfont-size
    • Ccolor
    • Dline-height
    看解析
    正确答案：A 盒模型类属性（width / height / margin / padding / border）都不继承，这是 CSS 的基本设计——否则给父元素设个宽度，所有后代都被同一个宽度锁死了。 会继承的主要是文字相关属性：font-size、color、line-height、font-family、letter-spacing、text-align 等。 审查要点：看到有人写 * { font-size: 14px } 想「统一字号」其实是多余的（本来就继承），真正需要显式写的是那些不继承的属性。 延伸阅读：MDN · 继承 / CSS 属性分类
  9. 9.实现选择
    需求：定义一个品牌色变量，并在变量未定义时回退到一个安全值。正确写法是：
    • A
      .btn {
  color: var(--brand, #333);
}
    • B
      .btn {
  color: var(--brand) #333;
}
    • C
      .btn {
  color: var(--brand || #333);
}
    • D
      .btn {
  color: var(--brand, --safe);
}
    看解析
    正确答案：A var() 的第二个参数是回退值，用逗号分隔：变量未定义（或值无效）时取它。 这个语法在组件库里非常实用——组件自带一套兜底色，接入方可以选择性覆盖 --brand，不覆盖也能正常渲染。 · B：var() 后面直接跟另一个值是无效声明，整条 color 会被浏览器丢弃。 · C：CSS 里没有 || 运算符，这是把 JS 写法搬过来了。 · D：回退值必须是具体值，不能是另一个变量名（那样会变成字符串 --safe，对 color 来说无效）。真要链式兜底得写 var(--brand, var(--safe, #333))。 延伸阅读：MDN · 使用 CSS 自定义属性（变量）
  10. 10.实现选择
    需求：用 Grid 做一个两列等宽布局。下列写法正确的是：
    • A
      .grid {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
}
    • B
      .grid {
  display: grid;
  grid-template-columns: repeat(2 1fr);
}
    • C
      .grid {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
}
    • D
      .grid {
  display: grid;
  grid: 2 / 1fr;
}
    看解析
    正确答案：A 1fr 表示「一份剩余空间」，repeat(2, 1fr) 即两列各占一半。 B 是最容易漏看的一处语法错误：repeat() 的两个参数之间必须是逗号，写成空格会导致整条 grid-template-columns 声明无效——而且它不会报错，页面只是悄悄退化成单列堆叠，很容易在 review 中被放行。 C 定义的是三列，不符合需求。 D：grid 简写里的斜杠分隔的是 grid-template-rows / grid-template-columns，grid: 2 / 1fr 的含义是「两行、一列」，跟需求正好相反。 延伸阅读：MDN · grid-template-columns / repeat()
  11. 11.缺陷审查
    审查下面这段 CSS：设计稿要求卡片总宽正好 200px，但实测占了 242px。问题出在哪，该怎么改？
    现有代码
    .card {
  width: 200px;
  padding: 20px;
  border: 1px solid #ccc;
}
    • A默认盒模型下 padding 和 border 会额外加算，应补上 box-sizing: border-box;
    • Bwidth 应该用 max-width，改成 max-width: 200px;
    • Cborder 太粗，改成 border: 0;
    • Dpadding 应该用百分比，改成 padding: 10%;
    看解析
    正确答案：A 默认 box-sizing: content-box 时，width 只约束内容区，padding 和 border 往外叠加：200 + 20×2 + 1×2 = 242px，正好对上实测值。 改法： 
    .card {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 1px solid #ccc;
}
    加了 border-box 后，width 变成边框盒总宽，padding 和 border 向内挤压内容区，总宽锁定 200px。 顺带一句：现在主流做法是全局设一次 *, *::before, *::after { box-sizing: border-box; } ——审查时如果项目里没有这条全局重置，那么每一处手写的 width 都值得怀疑。 B 只是把上限压住，内容区实际只剩 158px，布局仍然错位；C / D 都是在绕开问题而不是解决它。 延伸阅读：MDN · box-sizing
  12. 12.缺陷审查
    审查下面这段 CSS：.badge 想定位在卡片右上角，实际却跑到了整个页面的右上角。原因是什么？
    现有代码
    .card {
  /* 只有静态样式 */
  background: #fff;
}

.badge {
  position: absolute;
  top: 0;
  right: 0;
}
    • A绝对定位的包含块是最近的已定位祖先，卡片缺 position: relative;
    • Btop 和 right 应该写成负值
    • C应该用 position: fixed; 而不是 absolute;
    • D缺少 z-index，被其他元素顶开了
    看解析
    正确答案：A position:absolute 的元素，其 top/right/bottom/left 是相对最近的已定位祖先（position 不为 static）计算的。找不到，就一路往上退到初始包含块（视口）。 所以卡片没设 position 时，badge 就直接贴到了页面/视口右上角——这是 CSS 定位里出现频率最高的一类 bug。 改法：给卡片补上定位上下文 
    .card {
  position: relative;
  background: #fff;
}
    注意 relative 本身不会移动卡片（没有偏移量），只是为子元素的绝对定位提供参照系。 C 是反向的：fixed 相对视口定位，只会让问题更严重。 D：z-index 管的是层叠顺序（谁盖谁），跟「相对谁定位」完全是两件事。 延伸阅读：MDN · position / 包含块
  13. 13.缺陷审查
    审查下面这段 CSS：.modal 设了很大的 z-index，却仍然被别的元素盖住。最可能的原因是什么？
    现有代码
    .modal {
  z-index: 9999;
}
    • Az-index 只对已定位元素生效，这里缺 position
    • B9999 还不够大，应该改成 999999
    • C需要加 !important 才能生效
    • Dz-index 不能用在 div 上，要换成 span
    看解析
    正确答案：A z-index 的作用前提是元素参与层叠上下文的排序，而 position: static（默认值）的元素不参与——属性会被直接忽略。加上 position: relative / absolute / fixed 之后才生效。 改法： 
    .modal {
  position: fixed;
  z-index: 9999;
}
    B 是典型的无效尝试：把 9999 加到 999999 通常还是被盖住，因为真正的原因不是数值不够。而且一旦 A 元素在某个层叠上下文内部，它的 z-index 再大也无法盖过那个上下文之外的元素——这时候要看的是父级有没有创建层叠上下文（transform / opacity<1 / filter / will-change / isolation:isolate 都会创建）。 C：!important 提升的是声明优先级，跟层叠顺序无关。 延伸阅读：MDN · z-index / 层叠上下文
  14. 14.缺陷审查
    审查下面这段 CSS：本意是给标题加 20px 上边距，结果整个 .section 被一起顶了下去（标题相对父容器的间距没出现）。这是什么问题，怎么修？
    现有代码
    .section {
  background: #f5f5f5;
}

.title {
  margin-top: 20px;
}
    • A父子外边距合并（margin collapsing），给 .section 加 overflow: hidden; 触发 BFC 即可
    • Bmargin-top 应该改成 padding-top: 20px; 写在 .title 上
    • C给 .section 加 margin: 0;
    • D给 .section 加 display: inline;
    看解析
    正确答案：A 外边距合并：当父元素没有 border / padding / BFC 隔断时，第一个子元素的 margin-top 会与父元素的 margin-top 合并成一个，表现为——间距「跑到了父元素外面」，父容器整体被顶下去，而标题相对父容器顶部并没有间距。 修法（任选其一，效果相同）： · 给父元素触发 BFC：overflow: hidden;（最常用，副作用最小） · 给父元素加 padding-top: 1px; 或 border-top: 1px solid transparent; · 父元素改用 flex / grid 布局（Flex 和 Grid 容器内不发生外边距合并） B 能「看起来修好」，但改的是内边距——如果设计稿要求的是外边距语义（比如相邻 section 之间要合并间距），换成 padding 会改变盒子尺寸，是另一种错误。 D：display:inline 会让块级布局彻底失效。 延伸阅读：MDN · 外边距合并 / BFC
  15. 15.缺陷审查
    审查下面这段 CSS：flex 布局里有一段很长的英文文本，把容器撑破了（出现了横向滚动条）。问题的根源和修法是？
    现有代码
    .row {
  display: flex;
}

.name {
  flex: 1;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
    • Aflex 子项的 min-width 默认是 auto，不会收缩到内容宽度以下；应显式设 min-width: 0;
    • B给容器加 flex-wrap: wrap; 让它换行
    • C给容器加 overflow: visible;
    • D给子项加 width: 100%;
    看解析
    正确答案：A 这段「三个属性都写对了却不生效」，是 flex 布局最经典的陷阱。 原因：flex 子项的 min-width 初始值是 auto，而 auto 对 flex 子项的含义是「不小于内容的最小尺寸」。所以哪怕写了 flex:1，子项也不会收缩到内容宽度以下——长文本直接把容器顶开，overflow:hidden 根本没机会生效。 修法： 
    .name {
  flex: 1;
  min-width: 0;      /* 关键 */
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
    审查口诀：flex 子项上出现 text-overflow: ellipsis，就往下找 min-width: 0。 B：flex-wrap:wrap 会让整个子项换行，不是截断文本，改变了设计意图。 延伸阅读：MDN · flex 子项的自动最小尺寸 / min-width
  16. 16.缺陷审查
    审查下面这段 CSS：伪元素 ::before 写好了样式但页面上什么都不显示。原因是？
    现有代码
    .tag::before {
  display: inline-block;
  width: 8px;
  height: 8px;
  background: #f00;
}
    • A伪元素必须有 content 属性，缺了它整个伪元素不会生成
    • B必须加 display: block; 才会显示
    • C伪元素应该用单冒号 :before
    • D必须加 position: absolute;
    看解析
    正确答案：A content 是伪元素的生成条件，不是可选装饰。缺了它，浏览器压根不会创建这个伪元素盒子，后面所有样式都不生效。 修法（哪怕不需要显示文字，也要给个空串）： 
    .tag::before {
  content: &quot;&quot;;        /* 关键：不能省 */
  display: inline-block;
  width: 8px;
  height: 8px;
  background: #f00;
}
    C 是个需要澄清的历史问题：单冒号 :before 是 CSS2 的老写法，浏览器仍然支持，不是错误。现代规范推荐双冒号 ::before 以区分伪类，但看到老代码里的单冒号不必当成缺陷报——除非项目规范要求统一。 B / D：display 和 position 都不是生成条件。 延伸阅读：MDN · ::before / content
  17. 17.缺陷审查
    同事在 review 里提出：下面这段选择器逗号周围的空格不规范，会导致 h3 选不中。这个意见对吗？
    被质疑的代码
    h1, h2 ,h3 {
  color: #333;
}
    • A不对。逗号前后空格（或没有空格）都不影响选择器语法，三个标题都会被选中
    • B对。逗号后面必须有空格，否则 h3 选不中
    • C对。逗号前面不能有空格，否则解析失败
    • D对。h3 和 { 之间必须有空格
    看解析
    正确答案：A 这条 review 意见是误报，应该驳回。 CSS 选择器列表里，逗号是分隔符，其周围的空白字符全部被忽略。 h1, h2 ,h3 与 h1,h2,h3 与 h1 , h2 , h3 完全等价，三个元素都会被选中。 设计这道题意在说明另一件事：审查也要避免吹毛求疵。 把格式偏好（空格位置、换行风格）包装成「bug」报出去，会消耗团队对真正缺陷的注意力，也会让 review 变成形式主义。 正确的做法是：格式问题交给 Prettier / Stylelint 自动处理，人工 review 只关注行为是否正确。这条代码唯一值得说的也就是格式不统一，但它不影响任何渲染结果。 延伸阅读：CSS 选择器规范 · 选择器列表 / 空白处理
  18. 18.缺陷审查
    审查下面这段 CSS：这是一个桌面优先（先写宽屏、再用 max-width 收窄）的样式表，但中等屏幕下 .card 的宽度不对。问题在于：
    现有代码
    .card { width: 25%; }

@media (max-width: 1200px) {
  .card { width: 33.33%; }
}

@media (max-width: 768px) {
  .card { width: 50%; }
}

@media (max-width: 1200px) {
  .card { width: 100%; }   /* 后写，反而生效 */
}
    • A媒体查询顺序错了。max-width 系列必须从大到小排列，否则大断点会覆盖小断点
    • B媒体查询不能嵌套，必须拆成独立文件
    • C应把 max-width 全部改成 min-width
    • D.card 应该在媒体查询外面写一次
    看解析
    正确答案：A CSS 没有「媒体查询特殊优先级」——媒体查询里的规则和普通规则一样，同权重时后写的赢。 这段代码最后又来了一个 max-width:1200px 的块。在 1000px 宽的屏幕上，第 2 块和第 4 块同时命中，后写的第 4 块覆盖前者，.card 变成 100%。 结果就是：1000px 下本该 3 列，实际变成 1 列——而且第 2 块那段代码完全死掉了，看起来在，永远不生效。 修法：桌面优先的 max-width 序列必须从大到小单向排列 （1200 → 768 → 480），每个断点只出现一次： 
    .card { width: 25%; }
@media (max-width: 1200px) { .card { width: 33.33%; } }
@media (max-width: 768px)  { .card { width: 50%; } }
@media (max-width: 480px)  { .card { width: 100%; } }
    反过来，移动优先用 min-width 时则必须从小到大排列。混用两套是维护噩梦，项目里应该统一选一种。 延伸阅读：MDN · 媒体查询 / 层叠顺序
  19. 19.缺陷审查
    审查下面这段 CSS：.tip 想用 position: fixed 固定在视口右下角，实际却跟着某个父容器一起滚动、定位也不对。最可能的原因是？
    现有代码
    .panel {
  transform: translateX(0);   /* 某处动画留下的 */
}

.tip {
  position: fixed;
  bottom: 20px;
  right: 20px;
}
    • A某个祖先元素用了 transform / filter / will-change，为 fixed 创建了新的包含块
    • Bbottom 和 right 应该用负值
    • C缺 z-index
    • D父元素有 overflow: hidden
    看解析
    正确答案：A 这是 position:fixed 最反直觉的一处规范：祖先元素上的 transform、filter、backdrop-filter、perspective、contain:paint、will-change: transform 都会成为 fixed 元素的包含块，让它表现得像 absolute 一样相对该祖先定位。 排查时最坑的地方在于：transform: translateX(0) 这种看起来什么都没做的声明（常是动画库的残留、或为了触发硬件加速加的）同样会触发。代码里没有任何「定位」相关的字眼，但 fixed 就是失效了。 修法： · 把 .tip 移出带 transform 的祖先（常配合 React Portal 挂到 body 下） · 或去掉祖先上那个不必要的 transform D 是常见误判：overflow:hidden 会裁剪 fixed 元素的内容，但不会改变它的定位参照系——症状不同，别搞混。 延伸阅读：MDN · position: fixed / 包含块（transform 的影响）
  20. 20.缺陷审查
    审查下面这段 CSS：.btn:hover 想让按钮在悬停时变色，但悬停时完全没反应。问题是什么？
    现有代码
    #submit {
  background: #1677ff;
}

.btn:hover {
  background: #0958d9;
}
    • A选择器权重不够：#submit（ID）压过了 .btn:hover，把 hover 提到同等或更高权重即可
    • B:hover 只能用在 a 标签上
    • C必须给 .btn 加 cursor: pointer; 才会触发
    • Dbackground 不能被 hover 改变，要改用 background-color
    看解析
    正确答案：A 权重比较（a,b,c,d 四位数，逐位比）： · #submit = (0, 1, 0, 0) —— 1 个 ID · .btn:hover = (0, 0, 2, 0) —— 1 个类 + 1 个伪类 ID 位（1）大于类位（0），所以 #submit 无条件胜出，hover 时颜色不变。 修法（按推荐程度排序）： 1. 把基础样式也改成类选择器 .btn { ... } —— 首选，把 ID 从样式表里彻底拿掉 2. 同等权重并后置：.btn:hover → #submit:hover（能生效但继续积累 ID 债务） 3. 用 !important —— 不建议，它会让后续所有覆盖都失效，是技术债的起点 审查要点：样式表里出现 ID 选择器本身就是该被标记的信号——它的权重太高，会让后面所有基于类的覆盖都失效，这也是为什么 BEM / CSS Modules / Tailwind 这类方案都刻意避开 ID。 B / C / D 都不对：:hover 对所有元素生效；cursor 只改鼠标指针形状；background 简写完全可以参与层叠。 延伸阅读：MDN · CSS 优先级（Specificity）
