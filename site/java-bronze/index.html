Question 1单选initialisation

What is wrong with the following Java program?

以下这段 Java 程序有什么问题？

次の Java プログラムのどこに問題があるか。

class testClass{
  public static void main(String[] args) {
    int a;
    System.out.println(a);
  }
}
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 B

Local variables get no default value in Java. The compiler rejects any attempt to read one before a value has been assigned. Instance and static fields do receive defaults (0, false, null), but 'a' here is declared inside main, so it stays uninitialised.

Java 的局部变量没有默认值，任何「先赋值再读取」之外的用法都会被编译器直接拒绝。实例字段和静态字段才有默认值（0、false、null），但这里的 a 声明在 main 里面，属于局部变量，所以必须显式赋值后才能使用。

Java のローカル変数には既定値がないため、値を代入する前に読み取ろうとするとコンパイルエラーになる。既定値（0・false・null）を持つのはインスタンス変数と static 変数だけ。ここで a は main の中のローカル変数なので初期化が必須。

Question 2多选final

Which of these are compile errors in the program above? (select all that apply)

以上程序中，哪些会导致编译错误？（多选）

このプログラムでコンパイルエラーになるものはどれか。（すべて選択）

public class xyz {
  int a;
  final int b;
  int c = 4;
  final String str = "hello world";
  public void func() {
    int d;
    String localstring = "hello everyone";
    str = localstring;
    System.out.println(str);
    System.out.println(d);
    System.out.println(a);
  }
}
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 A,C,D

A final field or variable can only be assigned once: assigning to 'str' inside func() is illegal. A final field also has to be assigned either at its declaration or in every constructor — 'b' gets neither. Local variables have no default value, so printing 'd' is an error. 'a' is an instance field, so it defaults to 0 and printing it is perfectly legal.

final 变量只能赋值一次，所以在 func() 里再次给 str 赋值是非法的。final 字段必须在声明时或每个构造器里完成初始化，b 两者都没有。局部变量没有默认值，所以打印 d 也是错误。而 a 是实例字段，默认值为 0，打印它完全合法。

final 変数は一度しか代入できないため、func() 内での str への再代入は不正。final フィールドは宣言時か全コンストラクタで初期化が必要で、b はどちらも満たしていない。ローカル変数に既定値はないので d の出力もエラー。a はインスタンス変数で既定値 0 を持つため出力は問題なし。

Question 7单选types

このプログラムをコンパイルして実行した結果はどうなるか。

class testClass{
  public static void main(String[] args) {
    int i=4;
    float f = 4.3;
    double d = 1.8;
    int c =0;
    if(i == f) c++;
    if(((int)(f+d)) == ((int) f) + (int)d) c+= 2;

  2. B
  3. C
  4. D
解析 / Explanation

正确答案 D

A decimal literal such as 4.3 is a double, and assigning a double to a float needs either a cast or an 'f' suffix — so 'float f = 4.3;' never compiles. Write 4.3f to make it legal; the loop conditions are red herrings you never reach.

像 4.3 这样的小数字面量默认是 double 类型，把 double 赋给 float 必须做强制转型或加 f 后缀，所以 float f = 4.3; 这一行就编译不过。写成 4.3f 才合法——后面的判断全是干扰，根本执行不到。

4.3 のような小数リテラルは double 型。double を float に代入するにはキャストか f サフィックスが必要なため、float f = 4.3; の時点でコンパイルできない。4.3f と書けば合法。後続の条件判定は到達しないので関係ない。

Question 8单选interface

What happens when this program runs?

这段程序运行时会发生什么？

このプログラムを実行するとどうなるか。

interface inter{
  void func();
}
class testClass implements inter{
  public void func(){
    System.out.println("hello world");
  }
  public static void main(String[] args) {
    inter x = new inter();
    x.func();
  }
}
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 C

An interface declares behaviour without implementing it, so 'new inter()' is meaningless and rejected by the compiler. You must instantiate a concrete class and hold it in an interface-typed reference: 'inter x = new testClass();'.

接口只声明行为而不提供实现，因此 new inter() 没有意义，编译器会直接报错。正确做法是实例化某个具体类，再用接口类型的引用去持有它：inter x = new testClass();

インターフェースは実装を持たないため new inter() は意味を持たずコンパイラに拒否される。具象クラスをインスタンス化し、インターフェース型の参照で保持する必要がある：inter x = new testClass();

try の後はまず catch、最後に任意の finally という順序が必須のため、try … finally … catch は不正。他は問題なし。try に catch と finally を同時に付けることはでき、空の catch ブロックも文法上は合法。RuntimeException は非検査例外なので func1() に throws 宣言は不要。

Question 13多选operators

Which statements about the >> and >>> operators are true? (select all that apply)

关于 >> 与 >>> 运算符，哪些说法正确？（多选）

>> 演算子と >>> 演算子について正しいものはどれか。（すべて選択）

int x = 5;
int a = x >> 1;
int b = x >>> 1;
int c = -1 >> 1;
int d = -1 >>> 1;
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 A,C,D

>> keeps the sign bit when shifting (arithmetic shift), >>> fills with zero (logical shift). They agree as long as the sign bit is 0, which is why non-negative operands give identical results. For -1 the bit pattern is all ones, so -1 >> 1 is still -1 and -1 >>> 1 becomes the large positive value 2147483647 — certainly not 0.

>> 移位时保留符号位（算术移位），>>> 则补零（逻辑移位）。只要符号位是 0，两者结果就一致，这正是非负操作数结果相同的原因。-1 的位模式是全 1，所以 -1 >> 1 仍是 -1，而 -1 >>> 1 会变成很大的正数 2147483647，绝不是 0。

>> はシフト時に符号ビットを保持し（算術シフト）、>>> は 0 を埋める（論理シフト）。符号ビットが 0 なら結果は一致するため、非負のオペランドでは同じ結果になる。-1 のビット列は全ビット 1 なので、-1 >> 1 は -1 のままだが、-1 >>> 1 は大きな正の値 2147483647 になり、0 にはならない。

Question 17多选exceptions

  4. D
解析 / Explanation

正确答案 D

Leaving off the access modifier gives package-private (default) access: visible inside the package, invisible outside it. public opens it everywhere, protected also admits subclasses in other packages, and private hides it even from the rest of its own package.

不写访问修饰符得到的是包级私有（默认）权限：同包内可见，包外不可见。public 会对所有地方开放，protected 还会额外允许其他包的子类访问，private 则连同一个包内的其他类都无法访问。

アクセス修飾子を書かないとパッケージプライベート（既定）アクセスになり、同一パッケージ内からのみ参照できる。public はどこからでも、protected は他パッケージのサブクラスからも許可し、private は同一パッケージの他クラスからも見えなくなる。

Question 19多选inner-class

Which statements make the program print 1? (select all that apply)

哪些语句能让程序输出 1？（多选）

プログラムに 1 を出力させる文はどれか。（すべて選択）

class testClass{
  int a=1;
  int b=1;
  int c=1;
  class innerClassTest{
    int a=2;
    int get() {
      int c=3;
      // insert statement here
      return c;
    }
  }
  testClass(){
    innerClassTest i = new innerClassTest();
    System.out.println(i.get());
  }
  public static void main(String[] args) {
    new testClass();
  }
}
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 A,C

Inside the inner class, the simple names resolve to the innermost declaration first: the local c=3, then innerClassTest.a=2, then the outer fields. 'b' only exists on the outer object, so 'c = b' picks up the outer b=1. 'this.a' inside refers to the inner instance's own a=2, which prints 2, and 'testClass.this.a' reaches the outer a=1.

在内部类里，简单名会从最内层向外解析：先是局部变量 c=3，然后是 innerClassTest.a=2，最后才是外层字段。b 只存在于外层对象上，所以 c = b 取到的是外层的 b=1。this.a 指向内部实例自己的 a=2（会打印 2），而 testClass.this.a 才能访问外层的 a=1。

内部クラス内では単純名は内側から解決される：まずローカル変数 c=3、次に innerClassTest.a=2、最後に外側のフィールド。b は外側のオブジェクトにしかないので c = b は外側の b=1 を指す。this.a は内部インスタンス自身の a=2（2 が出力される）、testClass.this.a で外側の a=1 に到達する。

Question 20多选casting

Which conversions can be performed without an explicit cast? (select all that apply)

下列哪些转换不需要显式强制转型？（多选）

明示的なキャストなしで行える変換はどれか。（すべて選択）

int i = 10;
long l = ???;   // from i
short s = 5;
char ch = ???;  // from s
float f = 1.5f;
long n = ???;   // from f
  1. A
  2. B
  3. C
  4. D
解析 / Explanation

正确答案 A,B

Java allows implicit widening when no information is lost: int fits in long and byte fits in short, so both convert silently. Going the other way (float to long) may lose the fractional part and needs a cast; short and char are both 16-bit but neither is a subtype of the other, so that cast is required too.

Java 允许不丢失信息的隐式拓宽转换：int 装得进 long、byte 装得进 short，两者都能自动完成。反向的 float 转 long 会丢掉小数部分，必须显式转型；short 和 char 虽然都是 16 位，但互不兼容，转换也需要显式转型。

Java では情報が失われない拡大変換のみ暗黙的に行われる：int は long に、byte は short に収まるため自動変換される。逆方向の float から long は小数部が失われる可能性があり明示的キャストが必須。short と char はどちらも 16 ビットだが互いに包含関係がないため、この変換もキャストが必要。
