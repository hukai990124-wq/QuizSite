01

架构基础与灾难恢复

先理解系统要达到的目标，再选择实现目标的服务。

术语

Region / Availability Zone

区域 / 可用区 / AZ

有什么用
用不同级别的故障隔离位置部署系统。
实现什么
区域由多个可用区组成；跨 AZ 设计应对机房级故障，跨区域设计可用于区域灾难恢复。
理解要点
子网属于单个 AZ；多 AZ 不等于多区域。
AWS 官方资料：Region / Availability Zone（新窗口） ↗
术语

Edge Location

边缘站点

有什么用
把内容或网络入口放到更靠近用户的位置。
实现什么
CloudFront 用边缘缓存降低访问延迟；Global Accelerator 使用边缘网络入口优化传输路径。
理解要点
边缘站点不是让你任意部署 EC2 的可用区。
AWS 官方资料：Edge Location（新窗口） ↗
术语

Shared Responsibility Model

责任共担模型

有什么用
明确 AWS 和客户各自负责的安全工作。
实现什么
AWS 负责云基础设施安全；客户负责数据、身份权限以及所选服务中需要自己管理的配置。
理解要点
使用托管服务仍需配置权限、加密和数据保护；责任随服务类型变化。
AWS 官方资料：Shared Responsibility Model（新窗口） ↗
术语

Well-Architected Framework

良好架构六大支柱

有什么用
从多个目标检查架构是否合理。
实现什么
覆盖卓越运营、安全性、可靠性、性能效率、成本优化、可持续性。
理解要点
成本最低不一定满足可靠性；应根据业务目标权衡。
AWS 官方资料：Well-Architected Framework（新窗口） ↗
术语

High Availability / Fault Tolerance

高可用 / 容错

有什么用
在组件发生故障时继续提供服务。
实现什么
高可用通过冗余、检测和切换减少中断；容错强调故障发生后仍持续运行。
理解要点
增加单机规格不能消除单点故障。
AWS 官方资料：High Availability / Fault Tolerance（新窗口） ↗
术语

Scalability / Elasticity

可扩展性 / 弹性

有什么用
让系统容量匹配工作负载。
实现什么
扩展性表示能增加处理能力；弹性表示随需求增减容量；横向增加实例，纵向改变单机规格。
理解要点
扩容不自动解决有状态会话、数据库热点或单点故障。
AWS 官方资料：Scalability / Elasticity（新窗口） ↗
术语

RTO

Recovery Time Objective · 恢复时间目标

有什么用
规定业务最多可以中断多久。
实现什么
指导选择恢复流程、预置容量和自动切换方案；例如 RTO 30 分钟要求在目标时间内恢复业务。
理解要点
RTO 衡量恢复时间；RPO 衡量可接受的数据丢失。
AWS 官方资料：RTO（新窗口） ↗
术语

RPO

Recovery Point Objective · 恢复点目标

有什么用
规定最多可以丢失多长时间范围的数据。
实现什么
指导备份间隔和数据复制方式；例如 RPO 15 分钟要求恢复点与事故时间的差距满足目标。
理解要点
每小时备份通常不能保证 15 分钟 RPO；还需考虑备份成功率和复制延迟。
AWS 官方资料：RPO（新窗口） ↗
术语

Backup and Restore

备份与恢复

有什么用
以较低日常成本保留可恢复的数据。
实现什么
事故后创建基础设施、恢复备份并启动应用。
理解要点
通常恢复较慢；备份可恢复性需要演练验证。
AWS 官方资料：Backup and Restore（新窗口） ↗
术语

Pilot Light

指示灯 / 核心资源常备

有什么用
用较少常驻资源保留恢复的关键基础。
实现什么
持续维护数据和核心依赖，事故时启动或扩展其余应用资源。
理解要点
与温备相比，平时并不运行完整的可服务应用环境。
AWS 官方资料：Pilot Light（新窗口） ↗
术语

Warm Standby

温备

有什么用
预先运行缩小规模的完整环境以缩短恢复时间。
实现什么
备用环境具备业务功能，故障后扩容并切换流量。
理解要点
容量较小不表示无需测试；配额、依赖和数据同步都影响恢复。
AWS 官方资料：Warm Standby（新窗口） ↗
术语

Multi-site Active/Active

多站点主动 / 主动

有什么用
让多个站点同时承接真实流量。
实现什么
一个站点故障时由其他站点承接请求；结合跨区域数据策略提高业务连续性。
理解要点
成本和写入冲突处理更复杂；不能简单认为一定零数据损失。
AWS 官方资料：Multi-site Active/Active（新窗口） ↗
术语

Stateless / Loose Coupling

无状态 / 松耦合

有什么用
让实例替换和组件独立扩展更容易。
实现什么
会话放在外部数据存储；通过队列或事件减少组件间的同步依赖。
理解要点
无状态是应用设计方式；不是说整个系统不保存数据。
AWS 官方资料：Stateless / Loose Coupling（新窗口） ↗
术语

Latency / Throughput / IOPS

延迟 / 吞吐量 / 每秒 I/O 次数

有什么用
区分系统性能瓶颈。
实现什么
延迟看一次操作多久完成；吞吐量看单位时间传输或处理多少；IOPS 看每秒完成多少次 I/O。
理解要点
更多 IOPS 不必然减少网络延迟；大文件传输更关注吞吐量。
AWS 官方资料：Latency / Throughput / IOPS（新窗口） ↗
术语

Durability / Availability

持久性 / 可用性

有什么用
分别评估数据丢失风险与服务可访问程度。
实现什么
持久性关注数据是否仍保存；可用性关注需要时能否成功访问。
理解要点
有冗余副本仍需备份，避免误删除或逻辑损坏同时传播。
AWS 官方资料：Durability / Availability（新窗口） ↗

02

计算、容器与应用入口

决定代码在哪里运行，以及如何扩展和接收请求。

服务

Amazon EC2

Elastic Compute Cloud · 云服务器

有什么用
运行需要操作系统控制权的应用。
实现什么
选择实例规格、操作系统和网络，运行 Web 服务、数据库或自定义软件。
理解要点
你负责来宾操作系统和应用管理；自动扩缩容需另行配置。
AWS 官方资料：Amazon EC2（新窗口） ↗
服务

Amazon EC2 Auto Scaling

ASG · EC2 自动扩缩容

有什么用
按需求调整 EC2 数量并替换不健康实例。
实现什么
配置最小、期望、最大容量及扩缩策略；跨多个 AZ 部署。
理解要点
负责实例容量；ELB 负责把请求分发给实例。
AWS 官方资料：Amazon EC2 Auto Scaling（新窗口） ↗
服务

AWS Lambda

无服务器函数

有什么用
按事件运行代码而无需管理服务器。
实现什么
响应 API、队列、文件上传或定时事件，按调用和执行资源计费。
理解要点
有执行时长、并发和运行环境限制；不是长期运行的普通虚拟机。
AWS 官方资料：AWS Lambda（新窗口） ↗
服务

AWS Fargate

无服务器容器计算

有什么用
运行容器而无需维护容器宿主机。
实现什么
为 ECS 任务或 EKS Pod 提供计算容量。
理解要点
Fargate 提供运行资源；ECS/EKS 提供编排。
AWS 官方资料：AWS Fargate（新窗口） ↗
服务

AWS Batch

批处理作业调度

有什么用
运行大量可排队的计算作业。
实现什么
根据作业依赖和资源需求调度执行，并管理相应计算环境。
理解要点
适合批处理，不是对用户请求逐次提供低延迟响应的入口。
AWS 官方资料：AWS Batch（新窗口） ↗
服务

AWS Elastic Beanstalk

应用部署与环境管理

有什么用
快速把应用代码部署为完整运行环境。
实现什么
协调 EC2、负载均衡、扩缩容和健康检查等资源。
理解要点
底层资源仍在你的账户中；不像 Lambda 以单个函数调用为核心。
AWS 官方资料：AWS Elastic Beanstalk（新窗口） ↗
服务

AWS Outposts

本地 AWS 基础设施

有什么用
把部分 AWS 计算与存储能力放到本地机房。
实现什么
以 AWS 管理的硬件支持低延迟、本地数据处理和混合架构。
理解要点
不是在普通服务器上自行安装全部 AWS 服务。
AWS 官方资料：AWS Outposts（新窗口） ↗
服务

实现什么
使用已有模板和应用组件，减少重复搭建。

运营商边缘计算

03

存储与数据保护

按对象、块、共享文件和归档需求选择存储。

服务

Amazon S3

Simple Storage Service · 对象存储

有什么用
存储文件、备份、静态资源和数据湖对象。
实现什么
用存储桶和对象键管理数据，支持版本控制、生命周期、复制与访问策略。
理解要点
不是供操作系统直接使用的块卷；对象接口与共享文件系统不同。
AWS 官方资料：Amazon S3（新窗口） ↗
服务

Amazon S3 Glacier

S3 归档存储类别

有什么用
以较低存储成本保留很少访问的数据。
实现什么
通过不同归档类别平衡取回速度、费用和最低存储期限。
理解要点
Instant Retrieval 可直接快速访问；Flexible Retrieval 和 Deep Archive 一般需先发起恢复。
AWS 官方资料：Amazon S3 Glacier（新窗口） ↗
服务

Amazon EBS

Elastic Block Store · 块存储

有什么用
为 EC2 提供可持久保存的块设备。
实现什么
支持不同性能卷类型、快照和加密，常用于系统盘与数据库。
理解要点
卷位于单个 AZ；跨 AZ 恢复通常用快照重新创建卷。
AWS 官方资料：Amazon EBS（新窗口） ↗
服务

Amazon EFS

Elastic File System · Linux 共享文件

有什么用
让多台计算实例共享文件目录。
实现什么
通过 NFS 提供弹性文件系统，支持区域和 One Zone 等存储选择。
理解要点
Windows 的 SMB/AD 场景通常考虑 FSx for Windows File Server。
AWS 官方资料：Amazon EFS（新窗口） ↗
服务

Amazon FSx (for all types)

托管专用文件系统家族

有什么用
使用具有特定协议或性能能力的共享文件系统。

提供 Windows File Server、Lustre、NetApp ONTAP、OpenZFS 等类型。
理解要点
根据现有应用协议和文件系统特性选择，不能把各类型看作同一套功能。
AWS 官方资料：Amazon FSx (for all types)（新窗口） ↗
服务

通过备份计划、保留规则和备份保管库集中调度与管理恢复点。

服务

混合云存储网关

有什么用
让本地应用使用云端支持的存储。
实现什么
通过文件、卷或虚拟磁带等接口连接云存储，并可使用本地缓存。
理解要点

AWS 官方资料：AWS Storage Gateway（新窗口） ↗
术语

Object / Block / File Storage

对象 / 块 / 文件存储

有什么用
根据应用访问方式选择存储模型。
实现什么
S3 通过对象 API 访问；EBS 为主机提供块设备；EFS/FSx 提供共享文件系统。

标准化账户、日志、安全和网络基线；用 OU 组织账户，用控制限制或检测偏离。
理解要点
预防性限制与检测性告警的生效方式不同。

10

成本、购买方式与容量

区分费用分析、预算控制、折扣承诺与容量保证。

服务

AWS Budgets

预算与费用提醒

有什么用
监控实际或预测费用是否接近预算。
实现什么
设置预算阈值、通知，并按支持的方式配置预算动作。
理解要点
普通预算通知不是一到金额就自动停止整个账户消费的硬上限。
AWS 官方资料：AWS Budgets（新窗口） ↗
服务

AWS Cost Explorer

费用分析与预测

有什么用
看清费用花在哪里以及如何变化。
实现什么
按服务、账户、标签等维度查看历史费用、趋势与预测。
理解要点
用于分析；资源实际变更需要另行执行。
AWS 官方资料：AWS Cost Explorer（新窗口） ↗
服务

AWS Cost and Usage Report

CUR · 成本和使用量报告

有什么用
获得更细粒度的账单与用量明细。
实现什么
将报告交给分析系统，用于自定义成本分摊、审计和查询。
理解要点
明细数据报告与 Cost Explorer 的交互分析界面不同。
AWS 官方资料：AWS Cost and Usage Report（新窗口） ↗
服务

Savings Plans

计算消费承诺折扣

有什么用
以一定期限的每小时用量消费承诺换取折扣。
实现什么
根据计划类型对符合条件的计算用量自动应用折扣。
理解要点
Compute Savings Plans 灵活性较高；计划本身不是容量预留。
AWS 官方资料：Savings Plans（新窗口） ↗
术语

On-Demand

按需购买

有什么用
在没有长期用量承诺时使用计算资源。
实现什么
按实际使用的受支持计费单位付费，适合不可预测或短期需求。
理解要点
按需计费不等于有保证的预留容量。
AWS 官方资料：On-Demand（新窗口） ↗
术语

Spot Instances

竞价实例 / 闲置容量

有什么用
以较低价格运行可中断工作负载。
实现什么
适用于可重试批处理、并行任务等，结合检查点、容量多样化和中断处理。
理解要点
容量可能被回收；不宜把唯一关键数据库放在无容错的 Spot 实例上。
AWS 官方资料：Spot Instances（新窗口） ↗
术语

Reserved Instances (RI)

预留实例折扣

有什么用
通过期限与配置承诺降低符合条件的实例费用。
实现什么
按 RI 类型和范围匹配用量；区域 RI 与可用区 RI 的容量效果不同。
理解要点
不要把所有 RI 都理解为自动预留容量；需区分区域与可用区范围。
AWS 官方资料：Reserved Instances (RI)（新窗口） ↗
术语

On-Demand Capacity Reservation

按需容量预留

有什么用
提前确保特定 AZ 内匹配配置的 EC2 容量。
实现什么
为关键启动需求保留计算容量，可按规则与折扣结合。
理解要点
容量保证与价格折扣是不同目标；不用的预留容量也可能计费。
AWS 官方资料：On-Demand Capacity Reservation（新窗口） ↗
术语

Dedicated Hosts / Dedicated Instances

专用宿主机 / 专用实例

有什么用
满足硬件隔离或许可证绑定要求。
实现什么
Dedicated Hosts 提供物理服务器分配与放置控制；Dedicated Instances 提供专用硬件上的实例隔离。
理解要点
需要按物理核心或套接字许可时，重点评估 Dedicated Hosts。
AWS 官方资料：Dedicated Hosts / Dedicated Instances（新窗口） ↗
术语

Right Sizing / Scheduling

资源规格优化 / 非工作时间停机

有什么用
减少闲置或过度配置的成本。
实现什么
依据负载调小规格、自动扩缩容量，并在合适时段停止非生产实例。
理解要点
停止实例后存储等资源仍可能收费，删除前需确认数据保留。
AWS 官方资料：Right Sizing / Scheduling（新窗口） ↗
术语

Data Transfer / NAT / Endpoint Costs

数据传输与网络处理费用

有什么用
把网络架构中的持续费用纳入设计。
实现什么
综合评估跨区域、跨 AZ、互联网出站、NAT 处理与端点使用等费用。
理解要点
私有路径不等于免费；应按流量模式和区域价格比较。
AWS 官方资料：Data Transfer / NAT / Endpoint Costs（新窗口） ↗

迁移、传输与混合架构

按“迁移整台服务器、数据库还是文件”选择工具。

服务

AWS Application Migration Service

MGN · 服务器迁移 / AWS Transform MGN 相关名称

有什么用
把原有服务器应用迁移到 AWS。
实现什么
通过持续复制和测试切换，将源服务器迁移为云端运行环境。
理解要点
适合服务器重托管；数据库持续迁移可单独评估 DMS。
AWS 官方资料：AWS Application Migration Service（新窗口） ↗
服务

AWS DataSync

在线数据传输

有什么用
自动在本地与 AWS 或支持的存储之间移动数据。
实现什么
配置传输任务、校验和增量同步，适合大规模文件与对象迁移。
理解要点
是数据搬运工具；Storage Gateway 为应用提供持续使用的存储接口。
AWS 官方资料：AWS DataSync（新窗口） ↗
服务

AWS DMS

Database Migration Service · 数据库迁移

有什么用
把数据库数据迁移到受支持的目标。
实现什么
支持全量加载和变更数据捕获，以减少迁移切换时的数据差距。
理解要点
异构迁移还需处理架构与代码兼容；DMS 不保证自动改写所有应用 SQL。
AWS 官方资料：AWS DMS（新窗口） ↗
服务

AWS Snow Family

离线物理数据迁移与边缘设备

有什么用
理解带宽不足时用设备搬运数据的架构模式。
实现什么
考纲与旧题常以 Snowball Edge 说明离线数据导入和本地处理。
理解要点
自 2025-11-07 起不向新客户提供 Snowball Edge 设备；AWS 计划于 2026-12-31 停止所有商业区域的 Snowball 支持。新项目需核对状态，并评估 DataSync、Data Transfer Terminal 或合作伙伴方案。
AWS 官方资料：AWS Snow Family（新窗口） ↗
服务

AWS Transfer Family

托管文件传输协议

有什么用
保留传统文件协议并使用 AWS 存储。
实现什么
为 SFTP、FTPS、FTP 等受支持协议提供管理能力，连接 S3 或 EFS 等后端。
理解要点
用于客户端按文件协议传输；DataSync 更侧重受管理的数据迁移任务。
AWS 官方资料：AWS Transfer Family（新窗口） ↗
术语

Migration Strategies / 7 Rs

迁移策略 / 七种 R

有什么用
决定每个工作负载应如何迁移或保留。
实现什么
评估 rehost、replatform、refactor/re-architect、repurchase、relocate、retain、retire。
理解要点
不是所有应用都应原样搬迁；停用无用系统也属于迁移决策。
AWS 官方资料：Migration Strategies / 7 Rs（新窗口） ↗
术语

CDC / Full Load

变更数据捕获 / 全量加载

有什么用
在迁移期间把目标数据持续追近源数据。
实现什么
先复制已有数据，再持续应用源数据库新产生的受支持变更。
理解要点
低停机不代表无需切换窗口、校验或应用连接调整。
AWS 官方资料：CDC / Full Load（新窗口） ↗
术语

Schema Conversion

数据库架构转换

有什么用
处理不同数据库引擎的数据定义与代码差异。
实现什么
评估并转换受支持的表定义、过程等对象，识别需人工改写部分。
理解要点
架构转换与搬运表数据是两类任务。
AWS 官方资料：Schema Conversion（新窗口） ↗
术语

File / Volume / Tape Gateway

文件 / 卷 / 磁带网关

有什么用
让不同类型的本地应用连接混合存储。
实现什么
文件网关提供文件协议；卷网关提供 iSCSI 块接口；磁带网关对接虚拟磁带备份工作流。
理解要点
按应用接口选择，不能把磁带归档当成普通共享目录。
AWS 官方资料：File / Volume / Tape Gateway（新窗口） ↗
