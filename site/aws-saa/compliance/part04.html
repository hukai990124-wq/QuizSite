Question 154

A company is building a voting system for a popular TV show. Viewers will watch the performances then visit the show's website to vote for their favorite performer. It is expected that in a short period of time after the show has finished the site will receive millions of visitors. The visitors will first login to the site using their Amazon.com credentials and then submit their vote. After the voting is completed the page will display the vote totals. The company needs to build the site such that can handle the rapid influx of traffic while maintaining good performance but also wants to keep costs to a minimum. Which of the design patterns below should they use?

一家公司正在为热门电视节目构建投票系统。观众将观看表演，然后访问节目网站投票选出他们最喜欢的表演者。预计展会结束后的短时间内，该网站将迎来数百万访问者。访问者将首先使用他们的 Amazon.com 凭据登录该网站，然后提交投票。投票结束后，页面会显示投票总数。该公司需要构建能够处理快速涌入的流量的网站，同时保持良好的性能，但也希望将成本降至最低。他们应该使用以下哪种设计模式？

  1. A

    Use CloudFront and an Elastic Load balancer in front of an auto-scaled set of web servers. The web servers will first call the Login With Amazon service to authenticate the user, then process the user's vote and store the result into a multi-AZ Relational Database Service instance.

    在一组自动扩展的 Web 服务器前使用 CloudFront 和 Elastic Load Balancer。 Web 服务器将首先调用 Login With Amazon 服务对用户进行身份验证，然后处理用户的投票并将结果存储到多可用区关系数据库服务实例中。

  2. B

    Use CloudFront and the static website hosting feature of S3 with the Javascript SDK to call the Login With Amazon service to authenticate the user. Use IAM Roles to gain permissions to a DynamoDB table to store the user's vote.

    使用 CloudFront 和 S3 的静态网站托管功能以及 Javascript SDK 来调用 Login With Amazon 服务来对用户进行身份验证。使用 IAM 角色获取 DynamoDB 表的权限以存储用户的投票。

  3. C

    Use CloudFront and an Elastic Load Balancer in front of an auto-scaled set of web servers. The web servers will first call the Login with Amazon service to authenticate the user. The web servers will process the user's vote and store the result into a DynamoDB table using IAM Roles for EC2 instances to gain permissions to the DynamoDB table.

    在一组自动扩展的 Web 服务器前使用 CloudFront 和 Elastic Load Balancer。 Web 服务器将首先调用 Login with Amazon 服务来对用户进行身份验证。 Web 服务器将处理用户的投票，并使用 EC2 实例的 IAM 角色将结果存储到 DynamoDB 表中，以获得 DynamoDB 表的权限。

  4. D

    Use CloudFront and an Elastic Load Balancer in front of an auto-scaled set of web servers. The web servers will first call the Login with Amazon service to authenticate the user. The web servers will process the user's vote and store the result into an SQS queue using IAM Roles for EC2 Instances to gain permissions to the SQS queue. A set of application servers will then retrieve the items from the queue and store the result into a DynamoDB table.

    在一组自动扩展的 Web 服务器前使用 CloudFront 和 Elastic Load Balancer。 Web 服务器将首先调用 Login with Amazon 服务来对用户进行身份验证。 Web 服务器将处理用户的投票，并使用 EC2 实例的 IAM 角色将结果存储到 SQS 队列中，以获得 SQS 队列的权限。然后，一组应用程序服务器将从队列中检索项目并将结果存储到 DynamoDB 表中。

Question 155

You are designing a photo sharing mobile app. The application will store all pictures in a single Amazon S3 bucket. Users will upload pictures from their mobile device directly to Amazon S3 and will be able to view and download their own pictures directly from Amazon S3. You want to configure security to handle potentially millions of users in the most secure manner possible. What should your server-side application do when a new user registers on the photo sharing mobile application?

您正在设计一个照片共享移动应用程序。该应用程序会将所有图片存储在单个 Amazon S3 存储桶中。用户将移动设备上的图片直接上传到 Amazon S3，并且可以直接从 Amazon S3 查看和下载自己的图片。您希望配置安全性以尽可能最安全的方式处理潜在的数百万用户。当新用户在照片共享移动应用程序上注册时，您的服务器端应用程序应该做什么？

  1. A

    Create an IAM user. Update the bucket policy with appropriate permissions for the IAM user. Generate an access key and secret key for the IAM user, store them in the mobile app and use these credentials to access Amazon S3.

    创建 IAM 用户。使用 IAM 用户的适当权限更新存储桶策略。为 IAM 用户生成访问密钥和秘密密钥，将它们存储在移动应用程序中并使用这些凭证访问 Amazon S3。

  2. B

    Create an IAM user. Assign appropriate permissions to the IAM user. Generate an access key and secret key for the IAM user, store them in the mobile app and use these credentials to access Amazon S3.

    创建 IAM 用户。为 IAM 用户分配适当的权限。为 IAM 用户生成访问密钥和秘密密钥，将它们存储在移动应用程序中并使用这些凭证访问 Amazon S3。

  3. C

    Create a set of long-term credentials using AWS Security Token Service with appropriate permissions. Store these credentials in the mobile app and use them to access Amazon S3.

    使用具有适当权限的 AWS Security Token Service 创建一组长期凭证。将这些凭据存储在移动应用程序中并使用它们来访问 Amazon S3。

  4. D

    Record the user's information in Amazon RDS and create a role in IAM with appropriate permissions. When the user uses their mobile app, create temporary credentials using the AWS Security Token Service `AssumeRole` function. Store these credentials in the mobile app's memory and use them to access Amazon S3. Generate new credentials the next time the user runs the mobile app.

    在 Amazon RDS 中记录用户的信息，并在 IAM 中创建具有适当权限的角色。当用户使用其移动应用程序时，使用 AWS Security Token Service“AssumeRole”函数创建临时凭证。将这些凭据存储在移动应用程序的内存中，并使用它们来访问 Amazon S3。用户下次运行移动应用程序时生成新凭据。

  5. E

    Record the user's information in Amazon DynamoDB. When the user uses their mobile app, create temporary credentials using AWS Security Token Service with appropriate permissions. Store these credentials in the mobile app's memory and use them to access Amazon S3. Generate new credentials the next time the user runs the mobile app.

    在 Amazon DynamoDB 中记录用户的信息。当用户使用其移动应用程序时，使用具有适当权限的 AWS Security Token Service 创建临时凭证。将这些凭据存储在移动应用程序的内存中，并使用它们来访问 Amazon S3。用户下次运行移动应用程序时生成新凭据。

    使用 S3 复制 API 将最近访问的内容复制到多个区域并从 S3 提供用户内容。 CloudFront 在每个区域具有动态内容和 ELB。从每个区域中的 ElastiCache 集群检索用户首选项，并利用 SNS 通知将用户首选项更改传播到每个区域中的工作节点。

  3. C

Retrieve user preferences from a DynamoDB table and leverage SQS to capture changes to user preferences with SQS workers for propagating DynamoDB updates.

    使用 S3 Copy API 将最近访问的内容复制到多个区域，并在每个区域的 ELB 之间从 S3 CloudFront 和 Route 53 基于延迟的路由提供用户内容。从 DynamoDB 表中检索用户首选项，并利用 SQS 通过 SQS 工作线程捕获用户首选项的更改，以传播 DynamoDB 更新。

  4. D

    Serve user content from S3. CloudFront with dynamic content, and an ELB in each region. Retrieve user preferences from an ElastiCache cluster in each region and leverage Simple Workflow (SWF) to manage the propagation of user preferences from a centralized DB to each ElastiCache cluster.

    从 S3 提供用户内容。具有动态内容的 CloudFront，并且每个区域都有一个 ELB。从每个区域的 ElastiCache 集群检索用户首选项，并利用简单工作流 (SWF) 管理用户首选项从集中式数据库到每个 ElastiCache 集群的传播。
